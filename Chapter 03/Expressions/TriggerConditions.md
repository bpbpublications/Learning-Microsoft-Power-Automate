# Trigger Conditions

## Overview

A **trigger condition** controls whether a Power Automate flow should continue after its trigger fires.

Instead of allowing a flow to run for every event, a trigger condition can restrict execution to events that meet a specific requirement.

This can help reduce unnecessary flow runs and keep automations focused on relevant events.

## Example Scenario

Suppose a flow is triggered whenever a new email arrives.

The flow should run only when the email subject contains:

```text
New Ticket
```

The trigger condition used for this scenario is:

```text
@contains(triggerOutputs()?['body/subject'],'New Ticket')
```

## How the Condition Works

The expression checks the subject returned by the trigger.

```text
triggerOutputs()
```

Accesses the output generated by the trigger.

```text
['body/subject']
```

Reads the email subject from the trigger output.

```text
contains(...)
```

Checks whether the subject contains the specified text.

Therefore:

```text
@contains(triggerOutputs()?['body/subject'],'New Ticket')
```

means:

> Run the flow only when the trigger's email subject contains `New Ticket`.

## Example

Consider these incoming emails:

| Email Subject               | Flow Runs? |
| --------------------------- | ---------- |
| New Ticket - Printer Issue  | Yes        |
| New Ticket - Access Request | Yes        |
| Weekly Team Update          | No         |
| Invoice Received            | No         |

The trigger condition prevents the flow from continuing for emails that do not contain `New Ticket`.

## Adding a Trigger Condition

After configuring the trigger:

1. Open the trigger's **Settings**.
2. Locate **Trigger Conditions**.
3. Add the expression:

```text
@contains(triggerOutputs()?['body/subject'],'New Ticket')
```

4. Save the flow.
5. Test the flow with matching and non-matching emails.

> **Note:** The exact location of trigger settings may vary as the Power Automate user interface evolves.

## Testing

### Test 1 – Matching Subject

Send an email with:

```text
Subject: New Ticket - Laptop Issue
```

Expected result:

```text
Trigger condition = True
Flow runs
```

### Test 2 – Non-Matching Subject

Send an email with:

```text
Subject: Weekly Status Update
```

Expected result:

```text
Trigger condition = False
Flow does not run
```

## Why Use Trigger Conditions?

Trigger conditions can be useful when:

* A trigger responds to many events.
* Only specific events require processing.
* You want to avoid unnecessary flow runs.
* You want to reduce unnecessary downstream actions.

The condition should be designed around the actual business requirement rather than added unnecessarily.

## Troubleshooting

### Flow Does Not Run

Check:

* The expression is entered in **Trigger Conditions**, not as a normal action expression.
* The trigger output contains the property being referenced.
* The text being searched for matches the expected value.
* The flow is enabled.

### Condition Does Not Match

Review the trigger output and confirm the actual value of the subject.

For example, check whether the subject is:

```text
New Ticket - Printer Issue
```

rather than a different property or field.

## Important Considerations

Trigger conditions are evaluated when the trigger event occurs.

A condition that evaluates to false prevents the flow from continuing. This is different from adding a condition action later in the flow, because later actions occur only after the flow has already started processing the trigger.
